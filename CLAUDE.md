# Sezim — правила работы для Claude Code

Проект: **Sezim** (Genesis ArtTech). Дедлайн сдачи — вс 22.11.2026, 23:59 (Астана); внутренний срок — вс 18:00.
Источник истины по продукту — `docs/brief.md` (исходный промпт команды). Стек: Next.js (App Router) + TS + Tailwind, Dexie, WebGL, Web Audio.

## Начало каждой сессии
1. Сначала прочитай этот файл (`CLAUDE.md`) и `docs/PROGRESS.md`.
2. Продолжай с раздела «В работе» / «Дальше» из PROGRESS.md.

## Сохранение работы
- После каждого законченного шага: `git commit` с понятным сообщением и `git push`.
- Веди `docs/PROGRESS.md`: что сделано, что в работе, что дальше, известные баги. Обновляй его после каждого шага (в том же коммите).
- Перед крупным изменением закоммить рабочее состояние, чтобы можно было откатиться.
- После каждого этапа ставь тег (`v0.1`, `v0.2`, `v0.3`) и пушь теги (`git push --tags`).
- `main` всегда рабочий: перед коммитом в main проверяй `npm run build`.
- Ключи и `.env.local` никогда не коммитить; в репо только `.env.example`.

## Правила кода
- Контракт типов — `core/types.ts`; менять только с причиной (отмечать комментарием «+»).
- Style Engine (`core/style-engine.ts`) — чистые детерминированные функции; никаких словарей «эмоция = цвет».
- Рендерер — один компонент + шейдер с uniform-параметрами (`core/gl/shaders.ts`).
- Без мёртвого кода, неработающих кнопок и фейковых эффектов; моки — только с явной пометкой.
- Если реального аудио нет (ссылка) — честно подписывать «оценка по метаданным».
- Строки интерфейса — в `core/strings.ts` (RU по умолчанию).
- Пакеты ставить только по необходимости и объяснять зачем.
