# Sezim — Days you can feel again

*Дни, которые можно почувствовать снова.*

Sezim собирает день из **текста, фото и песни** в живую сферу воспоминания и сцену дня. Цвет, техника обработки фото, ритм и дыхание сферы выводятся из ввода по явным правилам, а панель «Почему так выглядит» объясняет каждое решение цифрами.

**Демо: https://sezim-iota.vercel.app** — без входа. Данные хранятся только в вашем браузере (IndexedDB), у каждого посетителя свой дневник.

## Запуск (3 команды)

```bash
npm install
cp .env.example .env.local   # ключи необязательны: без них работает упрощённый анализ и голос браузера
npm run dev                  # http://localhost:3000
```

Production-сборка: `npm run build && npm start`. Node.js ≥ 20 (для тестов `npm run test:*` нужен Node ≥ 23).

При первом открытии архив сам собирает демо-дневник из 6 дней (3–6 с, прогресс виден на экране).

## Как проверить за 3 минуты

1. **Архив** (`/`): 6 разных сфер. Переключатель «Сферы / Лента»: в ленте дни идут подряд, это ленточный тест «один автор».
2. **День** («Открыть день»): сцена фото в технике дня, живая сфера, «Слушать день» (песня + голос), «Почему так выглядит», «Атмосфера дня», «Экспорт папки .zip».
3. **A/B**: на экране дня кнопки «Сравнить с другой песней» и «Сравнить с другим текстом». Меняется только одно, обе версии пересчитаны одним движком, ниже — «Что изменила музыка» / «Что изменил текст». Нагляднее всего на дне «Добила меня репетиция к зимнему балу» (17 ноября): текст другого дня или свой текст меняет технику, палитру и сферу. У песни по ссылке темп и лад можно поправить чипами под плеером — день пересчитается (подписано «заданы вручную»).
4. **Новый день** (`/new`): текст → фото → песня (файл или ссылка). Превью сферы и палитры меняется на каждом шаге, «Создать воспоминание» сохраняет день.
5. **Без LLM**: откройте `/?llm=off`. Внизу появится значок «LLM выключен»: модель не вызывается, день помечается «упрощённый анализ». Кнопка «Включить» возвращает LLM.

## Как это устроено

```
ввод ─┬─ текст ──► /api/analyze (LLM → JSON, zod, таймаут 8 с, кэш по хэшу ввода)
      │            └─ нет ключа / ошибка / таймаут / ?llm=off → упрощённый анализ (русские маркеры), пометка в дне
      ├─ фото ───► k-means палитра, яркость, контраст, насыщенность, температура
      └─ песня ──► файл: FFT → темп, энергия, яркость, лад (с уверенностью; неуверенный — «≈»)
                   ссылка: встроенный плеер + oEmbed → ОЦЕНКА по метаданным (подписана честно)
                         │
                         ▼
                  MoodProfile — непрерывный вектор (core/mood.ts)
                         ▼
                  Style Engine — чистые детерминированные функции (core/style-engine.ts)
                         ▼
             StyleTokens + explain[] ──► WebGL (свой GLSL: сцена + сфера) + Web Audio ──► IndexedDB (Dexie)
```

- **Нет словаря «эмоция = цвет».** Палитра берётся из фото (k-means + яркий акцент меньшинства пикселей — салют, огни), текст и музыка её сдвигают: тепло текста тянет снимки к своей температуре, лад меняет тёплую или холодную долю (с весом уверенности), энергия — насыщенность. Без фото палитра строится по непрерывной оси температуры текста: холод → сирень → тепло, в обход зелёного.
- **Смешанные состояния видны внутри одной сферы.** Оболочка — «внешняя» температура (фото, холодные детали), ядро — «внутренняя» (тёплые детали). Чем выше противоречие, тем отчётливее граница. У энергичного дня ядро — яркий акцент снимков.
- **5 техник** — один шейдер, техника задаётся набором uniform-параметров. Условия выбора явные (`scoreTechniques`); в «Почему» попадает только та причина, которая действительно тянет к технике.

  | Техника | Референс |
  |---|---|
  | Soft Strokes | импрессионизм: мазки и мягкий свет |
  | Geometric Tension | Кандинский: линии, пятна, жёсткая сетка |
  | Film Grain Night | плёночная фотография: зерно, виньетка, ореолы |
  | Ma / Quiet Minimal | японское «ма»: пустота как содержание |
  | Collage | коллаж: много кадров, плотная память |
- **Музыка**: темп задаёт дыхание сферы (вдох на такт) и ритм смены кадров, энергия — зерно и резкость, лад — температуру палитры, год и жанр — фактуру. Песня по ссылке — приблизительная оценка по метаданным: её вес пропорционален уверенности (жанр не распознан → 16%, найден → 40%).
- **Сфера** уникальна для каждого дня: сид из текста, палитры, признаков песни и времени создания (`core/orb.ts`).
- **Название дня** — 3–7 слов. С LLM его даёт модель. Без LLM оно собирается только из слов самого текста: у смешанного дня — холодная и тёплая фраза («Первый снег и тёплое какао»), иначе лучшая клауза с деталью. Изменить его можно кнопкой «Переименовать».

## Переменные окружения

Все только серверные (`.env.local` локально, Settings → Environment Variables на Vercel). Без них приложение полностью работает.

| Переменная | Значение | Зачем |
|---|---|---|
| `LLM_PROVIDER` | `anthropic` или `none` (по умолчанию) | анализ текста моделью |
| `ANTHROPIC_API_KEY` | ключ Anthropic | нужен при `LLM_PROVIDER=anthropic` |
| `LLM_MODEL` | необязательно, по умолчанию `claude-opus-5-5` | модель анализа |
| `TTS_PROVIDER` | `none` (по умолчанию), `openai`, `elevenlabs` | облачная озвучка: в коде есть, но не проверена (нет ключа) и в демо не используется — голос даёт синтез браузера |
| `OPENAI_API_KEY` / `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID`, `TTS_MODEL` | ключи и модель | только при облачной озвучке |

## Папка дня

«Экспорт папки .zip» собирает настоящую папку `ГГГГ-ММ-ДД_Название/`: `entry.json` (текст, дата), `photos/01.jpg…`, `song.json` (+ `song.wav`/`.mp3`, если песня — файл), `memory.json` (настроение, токены, объяснение, признаки фото), `thumb.png` (сфера), `voice.*` (только если озвучка была предрендерена).

## Тесты

| Команда | Что проверяет |
|---|---|
| `npm run test:orbs` | 200 случайных дней попарно различимы; один и тот же день → те же параметры; seed — ≥ 4 разных настроения, есть тёмное и смешанное; грустный тёплый день не даёт синюю/зелёную сферу |
| `npm run test:audio` | WAV с известным темпом и тональностью (6/6) + 192 синтетических трека: уверенно-неверных тональностей 0, темп верен с точностью до октавы |
| `npm run test:llm` | настоящий SDK против локального mock API: zod, обрезка диапазонов, таймаут 8 с, отказ/401/429/500 → упрощённый анализ |
| `npm run test:titles` | название без LLM: 3–7 слов и только слова текста (seed, крайние случаи, 1000 случайных текстов) |
| `npm run check:tokens` | контраст текста и фона по WCAG AA |

## Демо-дневник

6 дней одного автора — записи, фото и песни команды (`public/seed/seed-v2/day-N/`: `text.md`, `photo-*.jpg`, `song.json` со ссылкой YouTube, `meta.json` с датой). Дни проходят обычный конвейер создания дня: фото → палитра и свет, текст → `/api/analyze` (LLM или упрощённый анализ), ссылка → oEmbed и оценка по метаданным. Название, настроение, палитру и технику выдаёт система; рабочее название автора хранится только как справка (`authorTitle`, в `entry.json` экспорта). Песни — только ссылки, аудио в репозитории нет; список и авторы — `docs/tools.md`. Фото уменьшены, без EXIF, личные данные обрезаны. Результаты проверки и скриншоты — `docs/evaluation/seed-v2/`.

**Пересобрать демо-дни** (например, после того как на сервере появился ключ LLM): откройте `/?reseed=1` — демо-дни удалятся и соберутся заново, свои дни не трогаются. Новые посетители получают актуальную сборку автоматически.

## Честность и ограничения

- Записи и фото демо-дней — команды, предоставлены добровольно; голоса синтезированные (speechSynthesis браузера). Sezim не делает медицинских или психологических выводов: «Атмосфера дня» описывает день, а не человека.
- Песня по ссылке не анализируется как звук: темп и лад подписаны «приблизительная оценка по метаданным» или «заданы вручную». У демо-дней все песни — ссылки, поэтому другая песня меняет ритм, дыхание и фактуру, но не технику.
- Лад определяется уверенно на ясной гармонии. У поп-петель (Am–F–C–G) мажор и параллельный минор звучат одинаково, такой лад показывается как «≈» с альтернативой. Темп иногда ошибается в октаву (172 → 86 BPM). Анализ проверен на синтетических треках, не на живых записях.
- Живой ответ LLM проверяется только при наличии ключа. Без ключа проверен контракт (`test:llm`).
- Проверено в Chromium (Windows, Intel UHD 620), 1440×900 и 390×844. Safari и iOS не проверялись.
